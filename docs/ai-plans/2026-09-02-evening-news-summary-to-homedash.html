Evening News summaries in HomeDash

Approved and in implementation

Task summary

Show the AI-generated Evening News summary when a user taps a news item in HomeDash. Do not transfer or render the original article text.

Current behavior

Evening News GET /api/v1/feed returns both summary and content. The Bridge currently reads only title, category, and publication time, then emits compact fields t, c, and h on /api/dashboard. Firmware receives only those fields; the current reader can therefore show only a complete title.

Desired behavior and contract

The Bridge will read Evening News summary, sanitize it for the display, and emit it as s. The compact dashboard news item becomes:

{ "t": "Headline", "s": "AI-generated summary", "c": "Technology", "h": 2 }

HomeDash will keep a short, non-scrolling title preview. Tapping the item opens the existing reader with the summary and category. If a summary is missing, the reader shows a clear “Summary unavailable” message; it never substitutes Evening News content.

Additional approved date behavior

When the local date changes, HomeDash must rebuild the seven-day strip, return to today unless the user explicitly selected another date, and request the new day’s calendar data from the Bridge.

Likely files

  • esp32-bridge/internal/fetcher/news.go — parse and sanitize summary from Evening News.
  • esp32-bridge/internal/model/model.go — add compact JSON field s to NewsItem.
  • esp32-bridge/internal/handler/handler_test.go — assert that dashboard output preserves summary and excludes original content.
  • homedash/src/bridge.h and homedash/src/bridge.cpp — hold and parse the compact summary field.
  • homedash/src/ui_dashboard.cpp — open the reader with the received summary and render a missing-summary fallback.
  • homedash/sim/stubs.cpp — add realistic summary fixtures for simulator QA.

Implementation and delivery

  1. Extend the Bridge model and fetcher with only summary; add tests against the dashboard payload.
  2. Build and publish the Bridge image via its existing main-branch CI, then deploy the scoped service and verify its live /api/dashboard payload contains s but not content.
  3. Extend firmware parsing and the reader UI; build the simulator and ESP32 firmware.
  4. Release a new HomeDash firmware tag, verify GitHub uploads firmware.bin, and verify the Bridge OTA check offers it to the current firmware.

Verification and manual QA

  • go test ./... in esp32-bridge.
  • Inspect live dashboard JSON after deployment: news entries include non-empty s and no original content.
  • make -C sim clean all and pio run in homedash.
  • On the physical display: open a news item, read a multi-line summary, scroll it, close it, then verify another item and navigation still work.
  • Verify GitHub release asset and the Bridge response to /api/ota/check.

Risks, boundaries, and rollback

  • Summaries can be longer than the former title buffer; firmware uses a bounded field and a missing-summary fallback.
  • The original article body remains deliberately excluded to avoid memory pressure and avoid duplicating third-party text on the display.
  • Bridge and firmware are rolled out in that order. Older firmware ignores the new field safely; new firmware degrades gracefully until the Bridge is updated.
  • Rollback is a scoped Bridge image rollback plus OTA to the prior firmware release.

Open questions

None for this scope. The Evening News source confirms that summary is the AI-generated summary and content is separate original text.

Actual changes and checks

Approved 2026-09-02. Bridge now maps Evening News summary to compact field s; a focused fetcher test confirms original content is not emitted. HomeDash now stores s in a bounded 1536-byte field per news item, renders it in the reader, and falls back when absent. The day-change handler refreshes the seven-day strip and requests the new current day unless a manual date selection is active.
